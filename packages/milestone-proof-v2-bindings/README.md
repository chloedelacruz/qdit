# `@qdit/milestone-proof-v2-bindings`

A typed TypeScript client for [`milestone_proof_v2`](../../contracts/milestone_proof_v2) on
Stellar **testnet**, generated by `stellar contract bindings typescript`. It embeds the
current contract id from
[`DEPLOYMENTS.md`](../../contracts/milestone_proof_v2/DEPLOYMENTS.md), and a test fails if
the two drift apart.

```ts
import { Client, networks } from "@qdit/milestone-proof-v2-bindings";

const client = new Client({
  ...networks.testnet,
  rpcUrl: "https://soroban-testnet.stellar.org",
});

const { result } = await client.get_project({ project_id: "8f14e45f-…" });
```

Reads are simulations and need no signer. For writes, pass `publicKey` and a
`signTransaction` to the client, then `signAndSend()` the returned transaction. A
contract error comes back as an `Err` holding one of the `Errors` (codes 1 to 14, the
same as the contract's README).

## Regenerate

`src/`, `tsconfig.json` and `.gitignore` are generated. Don't edit them; regenerate
after any interface change or new deploy:

```sh
cd packages
stellar contract bindings typescript --network testnet --overwrite \
  --contract-id <current id from DEPLOYMENTS.md> \
  --output-dir milestone-proof-v2-bindings
git checkout -- milestone-proof-v2-bindings/package.json milestone-proof-v2-bindings/README.md
npm run build && npm test
```

The generator also writes its own `package.json` and `README.md`; the `git checkout`
keeps these. The generated code uses a constructor parameter property, which Node can't
strip, so this package keeps its own `tsconfig.json` instead of the shared base, and its
test reads `dist/`.
